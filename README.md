# PDXfixIT privacy policies

The privacy policy for each app the Sandberg family makes, served at https://privacy.pdxfixit.com/ by a Cloudflare
Worker (static assets only, no script).

| App | Policy |
|---|---|
| Arrow-Rama (Android and Wear OS puzzle game) | https://privacy.pdxfixit.com/arrowrama/ |

The index at https://privacy.pdxfixit.com/ lists every app. GitHub Pages is not used. This repo was renamed from
`arrowrama-privacy`; GitHub redirects the old name for git, but update any remote or link that still uses it.

## This repo owns the pages

An app supplies its policy **text**. This repo owns how every page looks and how it is made, so the pages stay
consistent with each other and with pdxfixit.com, and no app repo needs a page generator.

```
src/<app>/policy.md      the policy text for one app (the only thing an app changes)
src/_shared/<name>.md    text shared by every app's policy, included with `@include <name>`
build.py                 src/ -> public/<app>/index.html and public/index.html
public/                  what is deployed: built pages, plus files kept by hand (below)
site/wrangler.toml       the Worker and its custom domain
site/verify.sh           after a deploy, checks the live site matches public/
.github/workflows/       deploy.yml
```

### Change a policy

1. Edit `src/<app>/policy.md` (an app's own sections), or `src/_shared/<name>.md` (text every app shares, below), and
   set `updated:` in that file's front matter to the new date.
2. Run `python3 build.py` and commit `src/` and `public/` together.
3. Push to `main`. The deploy does the rest.

### Shared text

Text every app shares is written once, in `src/_shared/`:

```
src/_shared/rules.md      the rules every app follows, how long we keep data, children
src/_shared/closing.md    changes and contact
src/arrowrama/policy.md   its own intro, what the game sends, deleting data; includes the two above
```

A policy includes a partial with a line of its own, with blank lines around it: `@include rules`. A partial is the
same Markdown subset with front matter `updated:` only; it has no `# Title` and no `@include` of its own.

A page's "Last updated" is the newest of its own `updated:` and the `updated:` of each partial it includes. So
changing a shared file and bumping its date updates every app's page together, and no page can show a date older
than the shared text it carries. A section only one app has stays in that app's `policy.md`.

Never edit `public/<app>/index.html`, `public/index.html` or `public/_headers` by hand. The deploy runs
`python3 build.py --check` first and fails if `public/` is not exactly what `src/` builds.

### Add an app

Add `src/<app>/policy.md` (the folder name is the URL path: lowercase letters, digits, hyphens) and run
`python3 build.py`. The index lists it, always alphabetically by `name:` (case ignored). There is no way to set an
order, and a hand-reordered `public/index.html` fails the deploy's `build.py --check`.

### The policy.md format

A front matter block, then a small Markdown subset. `build.py` documents it at the top and rejects anything else.

```
---
name: Arrow-Rama                              # the app's name, as the index lists it
blurb: A puzzle game for Android and Wear OS  # the subheadline, and the line under the name on the index
updated: 16 October 2026                      # "Last updated" in the page header
url: https://isopix.app/                      # optional: where to get the app; the index links it (https only)
---
# Arrow-Rama privacy policy        the headline; one per page, first
## A heading
A paragraph with **bold**, *italic* and a [link](https://example.com).
- a list item, one line each
```

`url:` is where the product lives: a Google Play address for an Android app, the site for a web app. The index shows "Get it on Google Play" or "Open <name>" under the app, and an app with no `url:` (not released yet) gets no link. Links may go to `https:` or a path on this site. A heading is one line, and a list is only `- ` lines.
A line `@include name` on its own pulls in `src/_shared/name.md`. The contact address is written `{contact}`; an
email address or a `mailto:` link in the text is an error (see below).

### The contact address

The contact address is protected from spam harvesters. It is not written in plain text anywhere in this repo's files
or on a page. `build.py` holds it reversed and base64-encoded; each page carries that string in a `data-c` attribute,
and one small inline script builds the `mailto:` link in the browser. With scripts off, a reader sees "privacy at
pdxfixit dot com". Write `{contact}` where a policy needs it. `build.py` refuses a plain address or a `mailto:` link in
`src/`, and refuses to build a page that would contain one.

The script is allowed by its hash in the CSP (`script-src 'sha256-...'`), so `public/_headers` is generated by
`build.py` too: the hash and the script cannot drift apart. What this does not cover: harvesters that run scripts,
people who read the address off the page and type it, and copies already in the git history, which is public and not
rewritten.

### Security hardening

- **Headers** (`public/_headers`, generated): a strict CSP (no other origins), `Permissions-Policy` denying camera,
  microphone, location, payment and sensors, `Cross-Origin-Opener-Policy` and `Cross-Origin-Resource-Policy`
  `same-origin`, `nosniff`, no-cache. **HSTS is not set here:** turn it on once for the whole zone in Cloudflare
  (SSL/TLS, Edge Certificates), so every subdomain gets the same policy.
- **`/.well-known/security.txt`** (RFC 9116, generated): its contact is a link to this repo's private vulnerability
  reporting (GitHub: Settings, Security, "Private vulnerability reporting"; turn it on), not an email address.
  `Expires` is a constant in `build.py` (`SECURITY_EXPIRES`): move it forward at least yearly. `build.py` warns in the
  last 60 days.
- **No second public address:** `workers_dev = false` and `preview_urls = false` in `site/wrangler.toml`, so the site
  is only on its custom domain.
- **Workflow:** actions float on their rolling major tag (`@v7`) and flarepress on `v1`, by the owner's decision: a
  breaking change fails the deploy at once instead of lingering. `persist-credentials: false` leaves no token in
  `.git/config`.
- **Verified after every deploy:** `site/verify.sh` checks every page and `security.txt` byte for byte, with the
  CSP header.

### Preview locally

```
python3 build.py
python3 -m http.server -d public 8000     # http://localhost:8000/ (the _headers file is not applied locally)
```

`build.py` is stdlib-only, needs no network, and writes identical bytes every run.

## The look

The pages follow pdxfixit.com: the Newsreader serif, the brand brown (espresso in dark mode), orange accents, the
PDXfixIT badge at the top left, links back to pdxfixit.com. The CSS lives in `build.py`, so every page changes together.
The badge, the footer and the headline block are in the same file.

Three files in `public/` are kept by hand and shared by every page:

- `logo-art.webp`: the logo artwork behind the badge, copied from pdxfixit.com's source.
- `favicon.ico`: the favicon, from the same place.
- `newsreader.woff2`: a Newsreader variable font (weights 300 to 600) subset to printable ASCII plus
  `’ “ ” – — · ← → é ©`. A character outside that set falls back to Georgia. To add characters, fetch a new subset
  from Google Fonts with those characters in the `text=` parameter and replace the file.

## Hosting and deploy

- `site/wrangler.toml` defines the Worker `privacy-pdxfixit-com`, serves `public/`, and attaches the custom domain
  `privacy.pdxfixit.com`. `pdxfixit.com` must be a zone in the same Cloudflare account.
- `public/_headers` (generated by `build.py`) sets the response headers: no-cache, `nosniff`, a referrer policy and a
  strict CSP (no other origins; this site's own images and font, inline styles, and the one inline script, by hash,
  that builds the contact link). It is not served as a file.
- `.github/workflows/deploy.yml` runs on every push to `main`, in this order:
  1. `python3 build.py --check`: `public/` is a clean build of `src/`.
  2. `wrangler deploy` through [flarepress](https://github.com/pdxfixit/flarepress), as pdxfixit/website does.
  3. `site/verify.sh`: every `public/**/index.html` is served byte for byte, with the CSP from `_headers`, five
     fetches in a row within 90 seconds. Cloudflare's edge can lag an upload, so one fetch proves nothing.
- Repo secrets: `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`. The token is this repo's own, scoped as
  pdxfixit/website's is: Workers Scripts: Edit, plus Workers Routes: Edit, DNS: Edit and Zone: Read on `pdxfixit.com`.
  No agent holds a token.
- To deploy by hand, from a checkout of flarepress: `just push /path/to/this/repo/site` (it uses
  `CLOUDFLARE_API_TOKEN` when set, else `wrangler login`). The workflow is the normal path.
- No `justfile` and no `site.conf`, as in pdxfixit/website: `build.py --check` and `site/verify.sh` do that work here.

### On the owner's Mac: the flarepress registry

flarepress's `just sites` (a read-only health check of every site) only sees site folders under
`~/.config/flarepress/sites/` (`$FLAREPRESS_SITES`). To register this one, from a flarepress checkout:

```
just link /path/to/this/repo/site         # a link named privacy.pdxfixit.com, from the site's first route
just sites privacy.pdxfixit.com
```

`just link` is safe to run again, and `just unlink privacy.pdxfixit.com` removes the link.

A folder without a `site.conf` is checked only for `/` answering 200; this site has no `site.conf`, so it is not
asked for `/version.json`.
